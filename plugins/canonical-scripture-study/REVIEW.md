# Review scope

This MVP makes retrieval, scope and stage contracts inspectable. A passing test does not prove a theological interpretation true or a translation correct.

The runtime reads a fixed source snapshot without writing to it. Source spans and metadata have pinned hashes; reconstruction markers and source versus derived annotations remain visible. Its textual selector cannot elect readings by theological usefulness, brevity or a corpus vote. The host model still supplies linguistic judgment, cross-edition alignment and exegetical/theological argument.

The reviewed working theology is a preferred, correctable framework. No denomination or systematic-theology model is the default teaching system. The website is a project source, not a completed imported doctrinal profile. Review each significant claim in context, reproduce a meaningful alternative fairly, and distinguish evidence from interpretation.

Published checks cover source integrity, native reference handling, continuation, word-study budgets, DSS reconstruction and pagination, apparatus parsing, reading assessment constraints, stage validation, MCP protocol behavior and packaging. See validation.json for actual results from this release. Missing cross-edition maps, full apparatus, wider lexical annotation and hosted deployment are acknowledged limitations, not completed features.

The free Cloudflare adapter has 1,921 matching comparisons with the Python runtime, including every base chapter boundary, all 50 word studies and all selected lexical lookup IDs. Its eleven tools retain read-only annotations and structured results, and the actual Worker HTTP handler passes the MCP protocol smoke check in Node and against local Wrangler/workerd over HTTP. Wrangler builds the Worker successfully with the expected ASSETS binding. Prepared asset count and maximum size fit the current free static-file limits. Live deployment, production CPU metrics and ChatGPT installation have not yet been verified; a local test is not proof that every dense study packet fits the 10 ms production CPU allowance. Dataset terms remain separate from the MIT code licence.

To report a problem, include the command/reference, plugin version, source commit, identified evidence and the smallest example showing the issue. Propose source-data changes separately from code and interpretive changes; preserve original source history and licences.
